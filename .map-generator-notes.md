# FOUND AND FIXED: the harness's clock started at a different place every run

**One line, `tools/map-qa/lib.mjs`, commit `ae71ec2`. The synthetic clock armed
at `realNow() - 10000`.**

Every synthetic timestamp is that origin plus a whole number of steps, and the
scene's loop takes its delta as `(frameNow - previousFrame) / 1000`. In float64
that subtraction rounds differently depending on the magnitude of its operands,
so with a different origin every server lifetime the crowd's accumulated time
came out a few **units in the last place** apart. The crowd draws every decision
from `hashUnit(agent.seed + this.elapsed)`, so once in a while a walker landed
the other side of a threshold, took a different turning, and spent the rest of
the run inside a building. Hence bimodality rather than noise — a handful of
distinct rounding patterns, each perfectly reproducible — and hence the other
worker seeing a fresh run reproduce an earlier one bit for bit across a restart.

The clock now arms at a fixed `0`. It is still behind any real timestamp the
page captured before capture began, which is all the old expression was for.

## The proof

The `entry` block is the crowd's own state at the instant capture begins.

# Superseded: "the build is pinned, and it is NOT SUFFICIENT"

Kept because the reasoning is what led to the fix above, and because the frame
pin it describes is still in the tree and still wanted.

What selected the mode was **how many real frames elapsed while the district was
being built**, before the synthetic clock took over. `lib.mjs` documented itself
as unable to pin exactly that, and it was right. The old `region()` called
`__clock.release()` for precisely the stretch in which the district is built, on
the reasonable-sounding theory that a build wants real frames; the count was
then whatever the machine's load allowed, and the district came out with a
different footway network on either side of some threshold. That is why a run
was never a draw from a distribution: it landed in one of a handful of discrete
worlds, each perfectly reproducible. The other map worker reached the same
conclusion from the vehicle-contact metric, where a fresh run reproduced an
earlier run bit for bit across a server restart, and a second fresh run exactly
reproduced a different one.

**The build wants no frames at all.** It is synchronous inside a React effect
and everything it waits on is a promise, so polling on an interval with the
capture still armed builds the same district every time, with an elapsed real
frame count of exactly zero. `region()` now does that, and additionally rebuilds
the district even when the page has already landed on it — the one the app
arrives on was built while the harness was still signing in, with an unpinned
frame count, so it was never safe to measure.

**So: real frames during the build are not the whole selector, or not the

variation is now provably removed, which narrows the search rather than ending
it.

## What actually varies, and where the branch lives

`inside.mjs` does not measure geometry. It ticks 900 frames and samples
`crowd.walkers[].rig.root.position` — it is a measure of **where the walkers
went**, over a network now proven identical. `samples` differing by one is one
walker-frame of population difference, not a missing footway; `hits` 28 -> 147
is the same crowd taking different routes.

The crowd's every decision is drawn from `hashUnit(...)` in `map-agents.ts`,
seeded per agent, and the two suspects visible from outside are:

- `hashUnit(agent.seed + this.elapsed)` at the re-routing and dwell decisions
  (~lines 1239, 1256). `elapsed` is accumulated simulated time over the sim's
  whole life, so **any** time the sim runs before the harness takes control
  shifts every subsequent decision for every agent. This is the mechanism that
  survives my frame pin: the pin removes frames during the *build*, but the
  crowd sim starts as soon as it exists, and whatever it accumulated before the
  first `tick` is carried in a float that feeds every later hash.
- `this.spawnCursor`, which indexes the spawn hashes and increments per spawn,
  so an extra spawn before capture permanently offsets the spawn sequence.

Both are in `map-agents.ts`. I did not edit it — reading the sim's state is
observation, and changing the sim would alter the thing being measured.

# The original finding, kept for the record

**The map harness is not as reproducible as every document in this repository,
including the earlier sections of this one, assumes it is.** Established the
evening of the 10th, by accident, in a control run:

| what | Old Quarter footway-in-solid share |
| --- | --- |
| untouched tree, freshly started dev server | **.0021** |
| the same untouched tree, server that had hot-reloaded through six edits | **.0109** |
| the same untouched tree, a second cold server, later | **.0109** |
| the same untouched tree, a third cold server | **.0021** |

Same commit, same probe, same machine. `solids 47912` and `facades 783`
identical to the unit in every run, so the scene's static geometry is stable;
`samples` moved by one and `hits` by 28 -> 147. Something in the **footway
network** comes out differently between server lifetimes, and a five-fold
difference on a district whose whole measured range today was .0021 to .0568 is
larger than most of the effects this harness has been used to judge.

## What this invalidates

Every three-replicate result in this file, and every "measured worse, reverted"
verdict taken on one. Replicates within a single server lifetime agree to four
digits -- which is exactly why this went unnoticed for a whole day: the metric
looks perfectly deterministic right up until you restart. An arm and its control
taken in different sessions were never comparable, and at least one of tonight's
reverts (the parcel reservation, .0379 against a control that could honestly
have been .0021 or .0109) was judged on that basis.

## The protocol, from now on

1. Restart the dev server. Do not measure on a server you have edited under.
2. Take the control **in the same session, on the untouched tree**, not from a
   number written down earlier.
3. Never compare across server lifetimes.
4. Treat anything under about 5x on the Old Quarter as unresolved until the
   bimodality below is understood.

`tools/map-qa/lib.mjs` now detects the first of these and prints a HOT SERVER
warning when any file under `frontend/src` is newer than the dev server process.
It cannot detect the rest, so the protocol still has to be followed.

## The open question, which somebody should take — ANSWERED, see the top

The two figures look bimodal rather than noisy -- .0021 or .0109, not a spread
between them -- and `samples` differing by exactly one suggests a single footway
run being emitted or cut differently. There is no `Math.random` in the map
modules, so the candidates are iteration order over a `Map`/`Set` keyed by
object identity, or something reading a real clock during the plan. Finding it
would make every number in this file mean something again, and it is probably
an hour's work with `plan-dump.mjs` diffing the network between two cold runs.

Note also that the browser began crashing outright ("Target crashed") on this

  to the plot instead, exactly as the Old Quarter courthouse already is.
- **Lattice anchoring.** `assembleAxis` drops the closer of any two lines within

  define a town fixes that.

### Why they failed: the map is held together by the zero-width ways

The reading that fits every arm, including this morning's:

A `half: 0` way is not merely a bad path. It is a **straitjacket**. A walker on
a way with no lateral freedom is pinned to the centreline, and the centrelines
are, by construction, the middle of the street. The Circuit's .0427 baseline —
four contact sites, all grazing, worst depth .06, all of them a cattle trough —
is *achieved by* the collapsed bands, not in spite of them.

`cutFootwaysAroundSolids` narrows a band only around **declared** solids. Most
of The Circuit is not declared: the farmsteads, the church, the field gates, the
cottage interiors and everything `bakeBatches` merges are invisible to it and
fully visible to the per-triangle audit. So the moment a band is allowed to
reopen — by shrinking the courthouse standing on it, by moving a compound off
it, by restoring the back lane it belonged to — the walkers it was holding on
the centreline spread out into geometry nobody ever declared. Arm C is the
cleanest demonstration: the *only* thing it does is make three set-pieces
smaller, and it takes the district from .0427 to .2396.

This is the same lesson the brief draws from attempt three, one level down.
Attempt three concentrated traffic by removing pavement; these arms diffuse it
by restoring pavement. Both make walkers-inside worse, because the pavement was
never the thing keeping people out of buildings — the *absence* of pavement was.

The corollary is the one useful piece of direction to come out of today:
**declaring solids improves the metric and freeing bands worsens it.** The
stalls commit is that corollary landed. The order of work for the next agent is
therefore inverted from the brief's: run `undeclared.mjs` per district, declare
what it finds, and only then fix the civic fit and the parcel siting. Fixing the
geometry first, on this map, is measurably harmful.

## Authoring the landmark sites from the street plan

The seventeen authored parcels — five headquarters and four rival compounds in
the Old Quarter, two and two on The Circuit, two and two on the Sovereign Arc —
were the only buildings in the game whose positions were written down rather
than planned. A table named a coordinate, the district then laid its streets,

### What changed

`siteOnPlan` inverts the relationship. The authored position becomes a request;
the plan answers with the nearest ground it has actually left free. Three
details are what make it work where three previous escape passes did not:

1. **The declared footprint, oriented.** The same rectangle `createLevelBuilding`
   and `createRivalBuilding` mark solid, tested with `clearanceIntrusion`'s
   support-width path, so a site that clears at siting time cannot be found
   overlapping at routing time.
2. **`plannedGround`.** The terraces go into the same segment field as the
   pavements, taken from `buildingAudit`. Every earlier pass worked from
   `crowdObstacles`, which cannot see an instanced building, so it could move a
   compound out of a lane and into a cottage without noticing. A rectangle is
   carried as the corridor along its own longer axis with the shorter
   half-extent for a width — the stadium that contains it.
3. **An ordered sweep, not a gradient.** Two pavements meeting at a corner give
   a gradient a local minimum it cannot leave, which is exactly why the escape
   pass reported sixteen of seventeen parcels with no clear ground within 3.4 m.
   That was a false negative. It is anisotropic for a headquarters, which is set
   back from a named stretch of route: a deeper forecourt on the same street is
   cheap, a slide up the road is expensive (`lateralCost`).

granted one is one line and it is the difference between a 30% regression and a
tenfold improvement. **A change that moves an object must also account for what
used to happen at the place it left.**

## The eleven unsitable parcels: root cause found, fix NOT landed (8:12–9:40 session)

Short version: the ordering flip in `planFootways` is **not** the fix, and
`planFootways` is not even in the right file. The parcels are stuck for two
reasons that are both upstream of it, both quantified below, and neither needs
a line of `map-agents.ts`. I ran out of session before I could measure a
change, so the tree is clean apart from tooling. **Nothing about the scene was
changed. The baselines are untouched.**

### What is actually stuck

| region | parcels | on asked | resited | stuck |
| --- | --- | --- | --- | --- |
| city (Old Quarter) | 9 | 0 | 0 | **9** — all five tiers and all four rivals |
| nation (The Circuit) | 4 | 0 | 3 | 1 (`tier-5`) |
| continent (Sovereign Arc) | 4 | 0 | 2 | 2 (`tier-10`, `tier-11`) |

### Why, measured rather than guessed

New probe, `tools/map-qa/blockers.mjs`, reports which *movement network*
records overlap a parcel — which is the question siting fails on, and which
neither `whatis.mjs` (triangles) nor `undeclared.mjs` (declared solids) can
answer. Run it as `node tools/map-qa/blockers.mjs city`; with no coordinates it
reads the stuck list out of the scene's own siting log.

**Fault one, the corridor building line.** Old Quarter's high street commits to
`KERB_OFFSET = .9` and `SETBACK = 1.95` in `addCityCorridor`, and records its
pavement centred at 1.43 with half-width .46 — so the paving runs out to 1.89
from the route centre and the shopfronts stand at 1.95. The tier table one
function away asks for a plinth centred at **2.80** with half-depth 1.275, so
its near face is at **1.525**, a third of a metre *inside* its own street's
pavement. Every one of the five is authored into the paving. No search radius
finds ground that was never left, which is why the failure looks like a siting
problem and is not one.

The fix is four lines and I wrote and typechecked it, then reverted it
unmeasured (see below). Publish the line where the corridor decides it:

```ts
// addCityCorridor, straight after recordCurveFootways(root, route, ...)
root.userData.corridorBuildingLine = SETBACK
```

and consume it where the table is read, instead of the typed figure:

```ts
const buildingLine = world.userData.corridorBuildingLine as number | undefined
const clearance = buildingLine === undefined ? setback[region] : buildingLine + 1.275 + WALKER_HALF_BEAM
const asked = roadPoint.clone().add(side.clone().multiplyScalar(Math.max(setback[region], clearance)))
```

That moves the Old Quarter headquarters from 2.80 to 3.385, and it is the same
principle as `streetHalfPaved`: the thing that lays the paving is the thing
that says where the building line is, so the two cannot disagree.

**Fault two, and this is the binding one.** With the setback corrected, all
nine city parcels are *still* stuck. The grid's north–south streets run
straight through the parcels. `tier-0` is authored at x = -10.64 and there is a
street at x = -10.42: its two pavements sit at -11.16 and -9.68, and the plinth
is 3.2 wide. It cannot fit between them, and clearing them outright needs a
lateral slide of about 2.8 against a budget of 1.2. The four rival compounds
are the same story — note that their ward blocks are *already* reserved
(`reserved` in `addCityEnvironment`, the hard-coded list at the four compound
coordinates), and `clearReserved` keeps planned buildings off them, but nothing
keeps the **street grid** off them. The reservation was only ever half a
reservation.

So the real ordering flip is one level up from where I put it in the last
handoff, and it is entirely inside files I own:

  today   `addPlannedStreets(streetsFromGrid(...))` lays every street and both
          its pavements across the whole lattice -> corridor runs -> tier and
          rival loops ask `siteOnPlan` to find a gap that was never left.
  wanted  derive the tier and rival parcels from the route curve *first*, put
          them in `reserved`, and have `recordStreetNetwork` split each
          pavement run — and, where it must, the carriageway — around them
          before recording, exactly as `onReserved` predicates already do for
          The Circuit's lanes (`map-three-scene.tsx` lines ~2723, 3719, 4124).
          The Circuit already does this and it is why only one of its four
          parcels is stuck rather than all four.

The authored positions are pure functions of `routeCurve` and the `authoredSides`
table, so they can be computed before the environment builders run at line
~7903 with no new information. That is the whole flip.

### Why I did not land it

The setback fix alone does not free a single parcel (measured: nine stuck
before, nine after), so shipping it would have been an unmeasured change to
five building positions with no win to justify it. Reverted. The grid
reservation is the half that pays and it is thirty minutes of careful work plus
three replicates a district, which I did not have.

**Do not run `inside.mjs` expecting the setback change to show.** It moves
buildings 0.585 m and frees nothing; it only becomes a win once the grid
reservation lets the parcels actually site.

### A hypothesis to kill

"The eleven parcels need a wider search." No. The lateral budget would have to
go from 1.2 to about 2.8 to clear a crossing street, and a parcel that slides
2.8 m has left the street it was authored against — which `authored.mjs` was
written to catch and already reports on The Circuit, where the two rival
compounds travelled 4.95 and 4.65. Widening the search converts a stuck parcel
into a parcel standing somewhere it does not belong, and the metric will not
tell you which you got.

### Why, and this is the part worth keeping

**The parcels are still stuck.** Nine of nine, before and after. Reserving the
*pavement* does not reserve the *carriageway*, and the grid's north–south
carriageways run through the parcels too: `tier-0` sits at x = −10.64 with a
street at −10.42, half .46, overlapping by .24; `tier-2` has a 0.97-half arterial
at gap 0.02. So the buildings did not move — and the pavement under them was
taken away while they stayed. That is the same shape as the three earlier
failures: **removing pavement from under a building that is still standing there
has now measured worse four separate times.** It is not a coincidence and it is
not the noise floor. Stop testing it.

One real bug was found and fixed on the way, and it is worth keeping in mind for
any future cut: the two pieces either side of a cut-out parcel were initially
given the *same* `street` id, and a shared id is precisely what tells the crowd
that two pavement ends facing each other are the two kerbs of one street. It
paired them into a crossing straight through the reserved parcel. Giving each
piece its own id took The Circuit from .1049 to .0704 by itself — a third of the
damage was walkers crossing the building. The remaining two thirds are not that.

### What the next agent should type first

The reservation is necessary and not sufficient. The missing half is that the
parcel has to end up somewhere the *carriageways* do not go, and there are only
two honest ways to do that:

  (a) Choose the parcel's position from the plan instead of from an even split
      of the route curve. `tierParcelSite` puts level *i* at
      `t = .12 + i / (n - 1) * .76`, which is a number with no relationship to
      where the streets are; landing it mid-block instead would remove the
      conflict at source rather than cutting anything. This is the one I would
      do, and `tierParcelSite` now exists as the single place to do it in.
  (b) Split the carriageways too. Cheaper to write and much more dangerous —
      the driving graph is what `portal` and the junction welding depend on,
      and a hole in it is a class of failure nobody has measured today.

Do **not** widen the search instead; that hypothesis is dead and the reasoning
is two sections up. And whatever is tried, the parcel must actually move — the
lesson of today is that clearing ground around a building that stays put makes
things worse every single time.

## Mid-block siting, and a measurement confound that undermines tonight's arms

### READ THIS FIRST: the dev server must be restarted before every arm

The control run at the end of this session, on a tree byte-identical to the
committed baseline, read **.0109 / .0086** where the same tree had read
**.0021 / .0040** an hour earlier. Same code, same probe, same machine. The
difference was that the second server had hot-reloaded through six edits.
Restarting Vite and re-running restored .0021 / .0040 exactly.

So **HMR-accumulated module state changes the scene**, and every arm measured
after an edit without a restart is inflated by an unknown amount. The static
geometry counts are unaffected (`solids 47912` matched to the unit both times),
so this is not the scene being rebuilt differently — it is something the crowd
or the network carries across a reload.

That is a five-fold inflation on the Old Quarter from nothing at all. **Every
figure in the two sections above was taken on a hot-reloaded server**, so the
"eighteen times worse" verdict on the reservation arm is not safe. It was still
clearly worse — .0379 against a .0109 contaminated control is 3.5x rather than
18x — but the honest position now is that the reservation arm has *not been
measured properly*, and the next agent should re-run it cold before accepting
the negative result. `git revert` of the two backouts brings it back.

Method from here: kill and restart Vite, then measure. Do not trust a figure
taken after an edit to the same server.

### The mid-block change itself

`tierParcelSite` now treats the even spread along the route as a preference
rather than a coordinate: it searches about one block either side of the ideal
`t` for the position with the most clearance from the region's cross-street
lines, and only the Old Quarter has a declared lattice to answer with, so only
it is affected. This is a choice about where a building is *authored*, made
before anything is built; it is not the search-widening hypothesis, which stays
dead.

It works. The five headquarters moved from -10.64, -5.32, 0, 5.32, 10.64 to
-12.32, -5.60, -0.42, 6.58, 10.78, and `blockers.mjs` shows them between
avenues rather than across one.

### And it is still not enough, for a reason that ends this line of attack

**The Old Quarter's headquarters does not fit between its avenues.** A tier-0
plinth is 1.45 half-width and needs 1.61 clear either side, so 3.22 m of free
width. The avenues flanking the corridor sit 4.08 apart and their kerbs leave
**2.94**. There is no position for it — not a search failure, a fact about the
district. All nine parcels stayed stuck, and the arm measured .0568 (worse than
the reservation alone at .0379 on the same contaminated basis). `stranded.mjs`
on this arm: 1 of 18 walkers parked, .0667, which is not a disconnection but is
not clean either.

### What is left, and it is now a design question rather than a bug

One of these has to give, and none of them is a fix to the siting code:

  (a) The headquarters gets narrower on the Old Quarter. 2.9 m of frontage is a
      townhouse, which is what a first office on a historic high street would
      actually be. Cheapest, and it makes the district read better rather than
      worse.
  (b) The avenue lattice is planned around the parcels. `planAxisInterior`
      generates the Old Quarter's interior avenue positions procedurally — only
      the three arterials at -18.6, 1 and 18.8 are named — so the filler lines
      could be nudged off a reserved parcel at plan time. This is the same
      ordering principle carried one level further up, and it is the one I would
      try, but the lattice is a module constant evaluated at import while the
      parcels depend on the route curve, so it needs the city's route to become
      a module constant first.
  (c) Accept that the Old Quarter's headquarters stand on the network and stop
      spending on it. Defensible: it is .0021 today, the best district on the
      map, and every attempt to improve it has cost more than it returned.

Do (a) before (b). And re-measure the reverted arms cold before anything else,
because the numbers they were judged on are not trustworthy.

Tonight's last forty minutes went on re-establishing the ground rather than on
the fix, which was the right trade: the fix was going to be judged by a metric
that turns out to disagree with itself.

**Cold re-run of the reverted arms: not completed.** I took a cold control, got

by eighteen times, and nobody currently knows.

**The per-piece street id fix is not separable, which I had not noticed.**
`spanOutsideReserved` returns the whole run untouched when nothing is reserved,
so there is only ever one piece and `piece === 0` always holds: without the
reservation the id fix is inert and cannot be landed or measured on its own. It
is a correct fix and it belongs with the reservation whenever that comes back.
The reasoning stands on its own merits — a shared id is what tells the crowd two
pavement ends are the kerbs of one street, and across a cut-out parcel that is a
crossing through a building — and it moved The Circuit .1049 to .0704, though on
the contaminated basis above.

**The Old Quarter width question is left for the user**, as asked. The finding
is that a tier-0 plinth needs 3.22 m of clear width and the avenues flanking the
corridor leave 2.94, so no siting code can place it. My recommendation is to
narrow the Old Quarter headquarters to roughly a 2.6 m frontage: a first office
on a historic high street *is* a townhouse, so this reads better rather than
worse, and it is the only option that does not involve either deleting streets
or replanning the lattice. But it changes what the player's first office looks
like, so it is theirs to decide.
